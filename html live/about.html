About TARA

Transit Analysis & Recognition AI · तारा
AI-powered detection & classification of exoplanets from noisy TESS light curves.

What it does

When a planet crosses in front of its star, the star gets very slightly dimmer for a few hours — a transit. TARA watches a star's brightness over time (its light curve) and hunts for that tiny repeating dip.

For any TESS star — or an uploaded FITS file — it finds the repeating dip, classifies it as a planet transit, false positive (usually two stars eclipsing each other), or noise, measures the transit with real ±1σ error bars, and shows the evidence behind every verdict. It is a candidate-finder and first-pass vetter — the same role automated pipelines play at NASA — not a final arbiter.

How the pipeline works

  1. load — fetch the light curve from NASA's MAST archive; if no ready-made curve exists, extract one from the full-frame images. Uploaded FITS files skip this entirely.
  2. clean — normalize, remove the star's slow brightness trends, clip outliers.
  3. search — a coarse BLS scan over all trial periods, then TLS refines the best one using a realistic limb-darkened transit shape.
  4. features — measure depth, duration, signal-to-noise, and the four vetting diagnostics.
  5. centroid — check whether the star's light-centre shifts during the dip (the signal would belong to a neighbouring star).
  6. fit — a trapezoid fit on the folded curve gives ±1σ uncertainties on period, depth and duration.
  7. cnn — a 5-seed deep-learning ensemble reads the folded light curve directly, as a second opinion.
  8. classify — a RandomForest turns the measurements into the primary verdict.

Every analysed star shows this trace live in the dashboard's Pipeline tab, with real per-stage times. A fresh star takes ~15–90 s (dominated by the NASA download + period search); cached stars answer in milliseconds.

How the model was built

Two models work together. The RandomForest classifies from 10 measured physics features (depth, U-vs-V shape, secondary eclipse, odd–even difference, centroid shift…) into four classes — transit / eclipsing binary / blend / noise — trained on 2,055 ExoMiner++-labeled TESS stars whose features were measured by this same pipeline. The deep-learning model is a multimodal 1D-CNN: two convolution branches read the phase-folded light curve — a wide "global" view (2001 bins) and a zoomed "local" view (201 bins) — while a third branch reads 11 stellar/transit parameters.

The CNN was trained cross-mission: 6,923 Kepler stars (DR25 catalog — confirmed planets vs known false positives) plus ~7,300 labeled TESS signals (ExoFOP TOI dispositions + NASA's ExoMiner++ catalog). The train/test split is grouped by star, so no star ever appears in both — the honest way to score (we caught and fixed three leakage traps getting here).

Honest limits

  • Some false positives are photometrically indistinguishable from planets — every check passes and both models say planet. Only follow-up observations (pixel difference-imaging, ground photometry, spectroscopy) resolve those. No light-curve-only system can, including NASA's.
  • Stars without a ready-made light curve fall back to FFI extraction — noisier data, so their diagnostics deserve less trust.
  • On a completely new catalog the score drops toward ~0.72 (domain shift — measured deliberately, most teams don't). The finale plan: retrain on ISRO's curated dataset, which brings performance back to ~0.95 within-distribution.
  • If the search finds no transit at all, TARA says "noise — no signal" rather than letting the classifier guess on empty features.

Data & tools

Data: NASA MAST (TESS light curves & full-frame images) · TESS Input Catalog (star properties) · Kepler DR25 KOI catalog · ExoFOP TOI dispositions · NASA ExoMiner++ labeled catalog.

Stack: lightkurve · Transit Least Squares · PyTorch · scikit-learn · batman + emcee (Bayesian fitting) · FastAPI. The dashboard is dependency-free HTML + canvas. Everything runs free on a laptop.
